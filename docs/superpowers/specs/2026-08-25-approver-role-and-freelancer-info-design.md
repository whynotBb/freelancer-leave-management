# 결재자 역할 도입 및 프리랜서 정보 관리 개편 설계 문서

- 작성일: 2026-08-25
- 상태: 승인 대기 (사용자 리뷰 전)
- 기준 문서: `docs/superpowers/specs/2026-08-24-freelancer-leave-management-design.md` (이하 "원 설계 문서")

## 1. 배경 및 목적

"프리랜서 정보 관리" 관리자 화면에 기능 수정 요청이 들어왔는데, 요구사항을 분석해보니 화면 하나를
고치는 수준을 넘어 **사용자 역할 체계 자체를 확장**해야 하는 변경이었다. 원 설계 문서는 역할을
관리자(HR)/프리랜서 2가지로, 결재자는 "역할이 아니라 필드로 지정되는 사람"으로 정의하고 있다
(원 설계 문서 3장). 이번 문서는 그 정의를 **결재자를 별도 역할로 승격**하는 방향으로 바꾸고,
그에 연쇄되는 화면·API·데이터 모델 변경을 정리한다.

이 문서는 원 설계 문서를 대체하지 않고, 아래 절을 **보강/수정**한다:
- 3장 (사용자 역할)
- 5.1절 (User 엔티티 — role 값 종류, position/department 제거)
- 9장 (GNB — 관리자 메뉴에 "결재담당자 관리" 추가, "연차 수동 조정"은 프리랜서 정보 관리 화면에
  통합되어 별도 메뉴로 만들지 않음)

## 2. 범위

**포함**
- 역할 모델을 `SUPER_ADMIN` / `APPROVER` / `FREELANCER` 3종으로 확장
- 프리랜서 정보 관리 화면: 직급/부서 제거, 입사일 수정, 기본 결재자 지정 UI(검색 콤보박스),
  사용가능·사용·미사용 연차 표시 및 수정(사유 필수), 검색, "담당 프리랜서만 보기" 토글
- 가입 승인 화면: 승인 시 권한(프리랜서/결재담당자) 선택
- 결재담당자 관리 신규 화면(조회 전용)
- 연차 조정을 원장(LeaveGrant/LeaveRequest)에 기록하는 메커니즘
- 연차 조정 시 실시간 알림 발송

**제외 (추후 별도 작업)**
- "내 휴가정보" 화면(연차 발생/사용 이력 상세 조회) 신규 구축 — 원 설계 문서 9장에 이미 계획되어
  있었으나 아직 미구현. 이번 조정 레코드는 그 화면이 만들어지면 바로 조회 가능한 형태로 남긴다.
- 결재담당자 관리 화면에서의 등록/삭제(CRUD) — 이번엔 조회만. 결재자 계정 생성은 가입 승인을
  통해서만 가능.
- SUPER_ADMIN 계정 생성 방식 변경 — 지금처럼 시드 스크립트로만 생성(기존과 동일, 이번 범위 아님).
- 프리랜서 → 결재자(또는 그 반대) 역할 전환(가입 승인 이후 역할 변경) — 이번 범위에서는 역할은
  가입 승인 시 1회 확정된다고 가정한다.

## 3. 사용자 역할 (원 설계 문서 3장 대체)

| 역할 | 코드값 | 설명 |
|---|---|---|
| 최고관리자 | `SUPER_ADMIN` | 기존 "관리자(HR)" 권한 전부 + 프리랜서 정보 전체 열람/수정 + 다른 사람의 기본 결재자로 지정될 수 있음 |
| 결재자 | `APPROVER` | 순수 관리 역할. 본인 휴가계 제출/연차 잔액 없음. 프리랜서 목록 전체 열람 가능, 본인이 기본 결재자로 지정된 프리랜서만 일부 필드 수정 가능(4장 참고). 다른 사람의 기본 결재자로 지정될 수 있음 |
| 프리랜서 | `FREELANCER` | 기존과 동일 — 휴가계 작성/제출/조회. 결재자로 지정될 수 없음 |

"기본 결재자" 후보 목록(가입 승인 화면, 프리랜서 정보 관리 화면 공통)은 `APPROVER` + `SUPER_ADMIN`
역할 사용자 전체다.

## 4. 프리랜서 정보 관리 화면

### 4.1 컬럼 구성

| 컬럼 | 표시/수정 |
|---|---|
| 이름/이메일 | 읽기 전용 (기존과 동일) |
| 입사일 | DatePicker로 수정 가능 (기존엔 읽기 전용 텍스트였음) |
| 기본 결재자 | 검색 가능한 콤보박스. 트리거를 누르면 이름 검색 입력 + `APPROVER`/`SUPER_ADMIN` 목록이 뜨고, 선택 즉시 반영(사유 모달 없음) |
| 사용가능 연차 | 숫자 입력, 수정 가능(사유 모달 경유) |
| 사용 연차 | 숫자 입력, 수정 가능(사유 모달 경유) |
| 미사용 연차 | `사용가능 − 사용` 자동 계산, 항상 읽기 전용 |

> **갱신 안내(2026-08-26):** 기본 결재자의 "선택 즉시 반영(사유 모달 없음)"은
> `docs/superpowers/specs/2026-08-26-freelancer-detail-panel-design.md`에서 사유 필수 모달
> 방식으로 대체되었다. 최신 내용은 해당 문서를 따른다.

직급, 부서 컬럼은 화면과 DB 스키마(`users.position`, `users.department`)에서 완전히 제거한다.

### 4.2 권한별 편집 범위

- **SUPER_ADMIN**: 모든 행에서 입사일 / 기본 결재자 / 사용가능·사용 연차 전부 수정 가능
- **APPROVER**: 전체 행을 열람할 수 있으나, **본인이 기본 결재자로 지정된 행만** 입사일과
  사용가능·사용 연차를 수정 가능. 기본 결재자 필드 자체는 APPROVER가 변경할 수 없다(재배정은
  SUPER_ADMIN 전용). 그 외 행은 인풋을 비활성화한 읽기 전용으로 표시한다.

### 4.3 사유 입력 모달

입사일 / 사용가능 연차 / 사용 연차 중 하나 이상을 바꾼 뒤 "저장"을 누르면, 저장 전에 작은 모달이
뜬다:
- 변경 전 → 후 값 요약
- 사유 입력(필수 텍스트)
- 확인 시에만 서버에 반영되고, 그 사유가 5장의 원장 조정 레코드에 함께 기록된다.

한 번의 저장에서 여러 필드가 바뀌었어도 사유는 하나로 묶어서 기록한다(필드마다 모달을 따로
띄우지 않는다).

### 4.4 검색 & 필터 (테이블 우측 상단)

- 검색창: 이름/이메일 기준 클라이언트 사이드 필터(서버 쿼리 불필요 — 현재 데이터 규모 기준)
- `APPROVER` 전용 토글 "**담당 프리랜서만 보기**": 검색창 오른쪽에 배치. 기본값 꺼짐(전체 목록).
  `SUPER_ADMIN`에게는 노출하지 않는다.

기존에 구현된 데스크톱 테이블 / 태블릿·모바일 카드 반응형 레이아웃 구조는 그대로 유지하고 위
변경사항만 반영한다.

## 5. 연차 데이터 모델 확장 — 조정 메커니즘

기존 잔여연차 계산(`lib/domain/leave-balance.ts`)은 `getCurrentCycle(hireDate, asOfDate)`로 구한
현재 사이클 구간에 날짜가 들어오는 `LeaveGrant`/`LeaveRequest`만 합산하는 구조다. 이 구조를 그대로
활용해 **새 테이블 없이** 기존 두 테이블에 조정 레코드를 추가하는 방식으로 처리한다.

**사용가능 연차 조정 → `leaveGrants`에 행 추가**
- `amount = 새 값 − 현재 합계` (음수 가능 — 예: 초과 지급 보정)
- `grantDate = 오늘` (현재 사이클에 자동 포함됨)
- `cycleEnd = getCurrentCycle(hireDate, 오늘).end`, `expired = false`
- `note` 컬럼(기존에 이미 존재)에 사유 저장
- 예: 야근/과중 업무에 대한 포상 휴가 부여

**사용 연차 조정 → `leaveRequests`에 행 추가**
- `requestedDays = 새 값 − 현재 합계` (음수 가능)
- `status = 'APPROVED'`, `startDate = endDate = 오늘`
- `type = 'ADJUSTMENT'` (신규 값 — 실제 신청 문서와 구분하기 위한 마커)
- `reason`(기존 notNull 컬럼)에 사유 저장, `approverId = 조정을 실행한 사람(본인)`
- 예: 시스템 도입 이전부터 근무 중이던 프리랜서의 기존 사용 연차를 관리자가 수기 기록에서
  옮겨 입력하는 경우

**부가 컬럼**: `leaveGrants`에 nullable `created_by`(조정자 userId) 컬럼을 추가해 "누가 조정했는지"
추적한다. `leaveRequests`는 `approverId`로 이미 추적된다.

**알려진 트레이드오프**: 입사일을 바꾸면 사이클 계산 기준(`getCurrentCycle`)이 바뀌므로, 과거
발생/사용 이력이 속하는 사이클도 소급 재계산된다. 이번 범위에서는 이를 별도로 보정하지 않고
자연스러운 결과로 받아들인다(입사일 수정은 예외적 케이스로 간주).

## 6. 조정 이력 알림

연차가 조정되면(5장) 원 설계 문서 7.1절의 실시간 알림 인프라를 재사용해 다음에게 알린다:
- 조정 대상 프리랜서 본인
- 그 프리랜서의 현재 기본 결재자 (조정을 실행한 사람이 그 결재자 본인인 경우는 제외)

`Notification.type`에 `LEAVE_ADJUSTED`를 추가하고, 메시지에 사유를 포함한다. 새 테이블 없이 기존
`Notification` 테이블/구독 구조를 그대로 사용한다.

"내 휴가정보" 상세 조회 화면은 이번 범위에 포함하지 않는다(2장 참고). 그 화면이 나중에 만들어지면
`type='ADJUSTMENT'`로 마킹된 레코드를 "관리자 조정" 배지 + 사유와 함께 표시하도록 요구사항을
남겨둔다.

## 7. 가입 승인 화면 변경

승인 처리 UI에 권한 선택(프리랜서 / 결재담당자, 기본값 프리랜서)을 추가한다.
- **프리랜서** 선택 시: 기존과 동일 — 입사일 필수(DatePicker). 기본 결재자는 이 화면에서 지정하지
  않아도 되며, 나중에 프리랜서 정보 관리 화면에서 지정 가능(기존 동작 유지).
- **결재담당자** 선택 시: 입사일 등 프리랜서 전용 입력은 숨기고 `role='APPROVER'`로만 저장한다.

SUPER_ADMIN 권한은 이 화면의 선택지에 없다(2장 참고 — 범위 밖).

## 8. 결재담당자 관리 (신규 메뉴, SUPER_ADMIN 전용)

- 사이드바에 "결재담당자 관리" 메뉴 추가
- 목록: 이름 / 이메일 / 역할 배지(최고관리자·결재자 구분) — `APPROVER` + `SUPER_ADMIN` 역할
  사용자 전체
- 조회 전용(CRUD 없음). 결재자 계정 생성은 가입 승인 화면을 통해서만 이루어진다.

## 9. API / 권한 게이트 변경

**서버 권한 함수** (`lib/auth/session.ts`)
- `requireSuperAdmin()`: SUPER_ADMIN만 통과 — 가입 승인, 결재담당자 관리, 기본 결재자 재지정
- `requireApproverOrAbove()`: APPROVER + SUPER_ADMIN 통과 — 프리랜서 정보 관리 화면 조회 게이트

**엔드포인트 변경**
- `PATCH /api/admin/signups/[id]`: `role`(`'FREELANCER' | 'APPROVER'`) 필드 추가.
  `role === 'FREELANCER'`일 때만 `hireDate` 필수.
- `GET /api/admin/users`: 게이트를 `requireApproverOrAbove()`로 변경. 응답 각 행에 서버가 계산한
  `canEdit`(SUPER_ADMIN=항상 true, APPROVER=본인이 기본 결재자인 행만 true) 포함.
- `PATCH /api/admin/users/[id]`: `requireApproverOrAbove()` + 내부에서 APPROVER는 자기 담당 행만
  허용(그 외 403). `defaultApproverId` 변경은 SUPER_ADMIN 전용. 입사일/연차 변경 시 `reason`
  필수 — 5장의 원장 조정 + 6장의 알림 발송을 수행한다.
- `GET /api/admin/approvers` (신규): `requireSuperAdmin()`, `APPROVER`+`SUPER_ADMIN` 목록 반환
  — 결재담당자 관리 화면과 기본 결재자 콤보박스 후보 목록에 공용으로 사용.

## 10. 데이터 마이그레이션

- `users.role` 값 마이그레이션: 기존 `'ADMIN'` → `'SUPER_ADMIN'`, `'FREELANCER'`는 그대로 유지.
- `users.position`, `users.department` 컬럼 삭제.
- `leaveGrants`에 nullable `created_by` 컬럼 추가.
- `leaveRequests.type`에 `'ADJUSTMENT'` 값 사용 시작(컬럼은 varchar라 스키마 변경 불필요, 도메인
  로직에서만 인식).
- `lib/db/seed-admin.ts`의 `role: 'ADMIN'` → `'SUPER_ADMIN'`으로 수정.
- `role === 'ADMIN'` 비교가 남아있는 기존 코드(`components/app-sidebar.tsx`의 `getRoleLabel`,
  `requireAdmin()` 등)를 3-역할 체계에 맞게 전부 재검토·수정.
- 이 작업의 일환으로 `CLAUDE.md`와 원 설계 문서 3장/5.1절/9장을 새 역할 체계에 맞게 갱신한다
  (구현 계획 단계의 작업 항목으로 포함).

## 11. 테스트 방향

- 역할별 권한 게이트: SUPER_ADMIN/APPROVER/FREELANCER 각각의 API 접근 가능/불가 케이스
- APPROVER의 행 단위 편집 제한: 본인 담당 행만 수정 성공, 타인 담당 행은 403
- 연차 조정 계산: 사용가능/사용 연차 조정 후 `calculateLeaveBalance` 결과가 기대값과 일치하는지
  (음수 조정 포함)
- 조정 시 사유 필수 검증, 사유 누락 시 차단
- 조정 시 알림(`LEAVE_ADJUSTED`) 레코드가 프리랜서 본인 + 담당 결재자에게 올바르게 생성되는지
  (조정자 본인이 담당 결재자인 경우 중복 알림 없는지 포함)
- 가입 승인 시 역할 선택에 따른 분기: 결재담당자 승인 시 입사일 없이도 처리 가능한지
- 기본 결재자 콤보박스 후보 목록이 APPROVER+SUPER_ADMIN으로 정확히 제한되는지
